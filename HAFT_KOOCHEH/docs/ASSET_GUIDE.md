# استاندارد Asset — مرحله ۰.۲

وضعیت: قرارداد فنی پیشنهادی برای بررسی؛ پالت نام‌برده مصوب دستور است، کد رنگ و
بودجه‌ها آزمایشی‌اند. هیچ Asset هنری نهایی یا فونت در این مرحله تولید/دانلود نشده است.
[TECHNICAL_DESIGN.md](TECHNICAL_DESIGN.md) و [GDD.md](GDD.md) مرجع محدودیت‌ها هستند.

## ۱. نام‌گذاری و مسیر

نام فایل ASCII کوچک با snake_case؛ بدون فاصله، حرف فارسی در path یا پسوندهایی مانند final_final.
الگو: `<region>_<subject>_<variant>_<state>_<index>.<ext>`؛ جزء نامربوط حذف می‌شود.
نمونه‌ها فقط نام پیشنهادی‌اند: bazaar_crate_a.png، hero_run_01.png، ui_pause.png،
bazaar_ambient_loop.ogg، sfx_coin_01.wav. برای فایل مشترک prefix منطقه حذف می‌شود.
بازنویسی فایل با همان نام باید نسخه کنترل‌شده داشته باشد؛ کپی v2 کنار فایل بلااستفاده نگه نداریم.

| پوشه موجود | محتوای آینده |
| --- | --- |
| assets/characters | قهرمان و sheet انیمیشن |
| assets/environments | tile، پس‌زمینه، دکور؛ زیرپوشه bazaar در زمان نیاز |
| assets/obstacles | موانع و خطر ثابت، از جمله ظاهر دشمن |
| assets/ui | آیکن، پنل و تصویر UI |
| assets/fonts | فونت مجاز فارسی و متن مجوز مربوط |
| assets/audio/music | موسیقی loop |
| assets/audio/sfx | افکت‌های کوتاه |

فایل‌های لایه‌باز تولیدی مثل PSD/ASE/AEP و masterهای WAV بزرگ بیرون درخت runtime
و با دسترسی کنترل‌شده هنرمند نگهداری شوند؛ نسخه خروجی لازم وارد پروژه شود.
ورود یک Asset جدید تنها پس از نیاز یک مرحله مصوب؛ pack کامل برای یک sprite وارد نشود.

## ۲. تصویر، واردسازی و Texture

خروجی دوبعدی معمول: PNG با alpha شفاف و رنگ sRGB. JPG فقط برای پس‌زمینه کاملاً
مات و با بازبینی artifact؛ SVG ساده برای آیکن مجاز است ولی rasterization و فونت
embedded باید روی Godot pinned تست شود. WebP یا فرمت دیگر نیازمند دلیل و تست جداست.
Art style نهایی pixel art فرض نشده؛ فیلتر Linear نقطه شروع و Nearest فقط برای
تصویر pixel art تأییدشده است. Mipmap برای UI/اسپرایت هم‌اندازه پیش‌فرض خاموش؛ برای
کوچک‌نمایی زیاد پس‌زمینه با تست روشن شود. فایل .import تولیدی داخل .godot commit نشود.

ابعاد بر پایه نمایش 1280×720 و scale طراحی نوشته شوند؛ بزرگ‌کردن مصنوعی تصویر
کیفیت محسوب نمی‌شود. توان دو برای همه تصویرها اجباری نیست. Atlas یا sheet در صورت
نیاز واقعی به batching، نه از اولین placeholder. ناحیه شفاف اضافه crop شود و pivot ثبت شود.

بودجه آزمایشی: sprite معمول حداکثر 512×512، atlas حداکثر 2048×2048 و هیچ بعدی
بیش از 2048 بدون بازبینی فنی. پس‌زمینه بزرگ به لایه/قطعه تقسیم شود تا بارگذاری
و حافظه کنترل شود. RGBA8 2048² بدون mipmap حدود 16 MiB حافظه می‌خواهد؛ حجم PNG
روی دیسک معیار RAM نیست. رنگ/UV/bleed در atlas روی Compatibility تست شود.
بهینه‌سازی compression بر اساس دستگاه میان‌رده هدف است؛ فرمت GPU آزمایش‌نشده تحمیل نشود.

## ۳. موسیقی و افکت

موسیقی OGG Vorbis استریو با loop بررسی‌شده؛ نقطه شروع آزمایشی 44.1 kHz و 128–160 kbps.
افکت کوتاه WAV PCM 16-bit، mono، 44.1 kHz؛ سکوت ابتدا/انتها حذف و بدون clipping.
فایل MP3 پیش‌فرض انتخاب نیست. تبدیل فرمت نباید مجوز منبع را از بین ببرد.
نام loop و طول قطعه در فهرست Asset ثبت شود؛ seam و تغییر volume با هدفون و گوشی
تست شود. باس‌های Music و SFX قرارداد آینده‌اند، نه فایل bus ساخته‌شده در این مرحله.

## ۴. فونت فارسی

فونت باید پوشش حروف فارسی، ی/ک فارسی، اعداد مورد استفاده، نیم‌فاصله و مجوز توزیع
در APK داشته باشد؛ TTF/OTF همراه فایل مجوز وارد شود. از فونت نصب‌شده شخصی توسعه‌دهنده
یا مجوز نامشخص استفاده نشود. انتخاب خانواده فونت نیازمند بازبینی هنری است؛ فعلاً نامی قطعی نیست.
متن UI ترجیحاً Unicode واقعی و RTL در Control است؛ حروف دستی برعکس/به هم چسبانده
نشوند. تست عبارتی شامل «بازار هزاررنگ»، «می‌پرم»، «۱۲۳»، «HAFT KOOCHEH» و
عدد/علامت مخلوط انجام شود؛ شکست خط و اندازه کوچک روی دستگاه بررسی شود.
پیچیدگی فونت و shaping باید روی موتور Standard و خروجی Android واقعی سنجیده شود؛
نتیجه Headless برای خوانایی فارسی کافی نیست. subset فقط با حفظ مجوز و پوشش متن‌ها.

## ۵. Animation

نام animationها snake_case: idle، run، jump، fall و hurt؛ پسوند جهت فقط در صورت
نیاز واقعی. Animation نام حرکت را با منطق state مخلوط نمی‌کند؛ signal شکست از فیزیک
می‌آید نه آخرین فریم انیمیشن. هر فریم یک اندازه/pivot ثابت نسبت به پای بازیکن دارد؛
تغییر collider از روی فریم ممنوع. run/idle می‌توانند loop شوند؛ jump/fall بر اساس
state حرکت انتخاب می‌شوند. نرخ آزمایشی 12 fps برای sprite animation فقط شروع طراحی
است و با نرخ فیزیک 60 یکی نیست. در این مرحله sheet یا AnimationPlayer ایجاد نمی‌شود.

## ۷. منبع، مجوز و حجم

هنگام ورود اولین Asset، فایل assets/ASSET_SOURCES.md ساخته خواهد شد؛ فعلاً
فایل فهرست خالی ایجاد نمی‌شود. هر ردیف شامل path دقیق، عنوان، سازنده، URL منبع،
تاریخ دریافت، نوع/نسخه مجوز، path متن license، تغییرات انجام‌شده و الزام attribution است.
Asset تولیدشده سفارشی هم مالک/شرایط استفاده و منبع تولید دارد؛ «رایگان» نام مجوز نیست.
در نبود حق توزیع روشن، Asset وارد پروژه نمی‌شود؛ آرت مرجع با آرت قابل انتشار اشتباه نشود.

فایل بیش از 5 MiB یا texture بیش از 2048 نیازمند توضیح مصرف و بررسی بودجه است؛
سقف آزمایشی کل runtime assetهای MVP برابر 64 MiB روی دیسک، نه سقف APK یا RAM.
هنگام import، حجم فشرده، RAM تقریبی، تعداد استفاده و محل مصرف ثبت شوند. cache، خروجی
build، duplicate و asset بدون reference وارد stage نمی‌شوند. Git LFS یا وابستگی جدید
بدون نیاز واقعی و تصمیم جدا اضافه نمی‌شود. حذف فایل مشترک فقط پس از بررسی همه referenceها.
