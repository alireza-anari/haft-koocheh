# گزارش مرحله ۰.۲ — HAFT KOOCHEH

## ۱. مشخصات مرحله

فاز صفر، مرحله ۰.۲: تثبیت معماری فنی، تکمیل GDD و استانداردسازی توسعه.
تاریخ: ۲۰۲۶-۱۱-۱۵. وضعیت: تکمیل‌شده در محدوده مستندسازی، آماده بررسی مدیر پروژه.
این وضعیت به معنی تأیید مدیریتی یا اجازه شروع مرحله ۱.۱ نیست.

## ۲. وضعیت اولیه

بسته HAFT_KOOCHEH_phase_0_1_R1.zip با ۱۸ فایل و همه بایت‌های فایل‌های Workspace
تطبیق داده شد. Git محلی موجود، فایل‌ها Stage، بدون Commit و Remote بود.
مرحله ۰.۱ طبق دستور جدید با استثنای QA-001 پذیرفته شده است؛ وضعیت ناقص در
گزارش‌های تاریخی همان نتیجه فنی زمان R1 را بیان می‌کند و حذف نشده است.
صحنه عنوان و ساختار پوشه‌ها موجود؛ اسکریپت گیم‌پلی، آرت و مرحله اجرایی وجود نداشت.

فایلی حذف نشده؛ پوشه‌های پایه حفظ شدند. project.godot، main.tscn، .gitignore و
validate_skeleton.py با مبنا از نظر بایتی یکسان‌اند. اسناد/لاگ‌های تاریخی دیگر تغییر نکرده‌اند.

## ۵. خلاصه معماری مطابق دستور و قراردادهای تدوین‌شده

PlayerController روی CharacterBody2D؛ Coin روی Area2D. LevelController تنها مالک
وضعیت تلاش و داوری نتیجه است. Collision/Hazard فقط تماس را گزارش می‌کند؛ Collectible
درخواست برداشت می‌دهد و ScoreManager محلی تلاش امتیاز را یک بار اعمال می‌کند.
SaveManager ذخیره نسخه‌دار محلی دارد؛ AudioManager فقط پخش/volume؛ UI نمایش و
درخواست کاربر است. Save/Audio/UI زیر App و Score/Level زیر تلاش‌اند؛ Autoload نداریم.
Signal، ورودی، خروجی، وابستگی و مسیر پیشنهادی هر هشت سیستم مستند شده است.
هیچ‌کدام از این سیستم‌ها در این مرحله ساخته نشده‌اند.

## ۶. تصمیمات جدید

DEC-013 تا DEC-032 اضافه شدند؛ بندهای ۱ تا ۱۲ قبلی بدون تغییرند. هر ردیف شناسه،
وضعیت قطعی/قرارداد پیشنهادی/آزمایشی، دلیل و اثر بر مرحله بعد دارد.
موتور Godot 4.7.2 Stable Standard و تنظیمات پایه قطعی باقی‌اند. یک شخصیت/یک منطقه
و عدم سرور MVP قطعی‌اند. اعداد حرکت 280،1200،-480،0.08 و0.10 آزمایشی‌اند.
طرح تفصیلی داستان، هویت مناطق آینده، امتیاز 10×سکه، دشمن ثابت، جدول چیدمان و
بودجه‌های هنر پیشنهاد برای بررسی‌اند؛ نگارش سند به معنی تصویب نهایی محصول نیست.
پرش ثابت، مسیر ورودی touch/Space، اولویت failure > coin > finish، حفظ داده خراب و
تفکیک طول عمر سیستم‌ها ابهام‌های اجرایی را در قرارداد روشن می‌کنند.

## ۷. نتایج واقعی تست‌ها

ENGINE مسیر واقعی ../tools/godot-4.7.2/Godot_v4.7.2-stable_linux.x86_64 است.
از ریشه پروژه دستورها اجرا شدند؛ مسیر کامل، stdout، stderr و exit در JSON آمده‌اند.

| تست اجباری | دستور / بررسی | نتیجه واقعی |
| --- | --- | --- |
| Static Validation | python3 tests/validate_skeleton.py | موفق، خروج صفر |
| Engine Version | ENGINE --version | 4.7.2.stable.official.ed1daf0bf؛ Standard، خروج صفر |
| Project Import | ENGINE --headless --editor --path . --quit | موفق، خروج صفر و stderr خالی |
| Headless Runtime | ENGINE --headless --path . --quit-after 3 | موفق، خروج صفر و stderr خالی؛ فقط smoke کوتاه |
| Documentation Consistency | python3 tests/validate_documentation.py --baseline ../HAFT_KOOCHEH_phase_0_1_R1.zip | موفق؛ لینک نسبی، IDs/نام ۱۰ مرحله، پنج پارامتر و فرمول امتیاز هماهنگ |
| File Structure Validation | همان تست با مقایسه بایتی مبنا | موفق؛ ۱۸ مسیر قبلی محفوظ، فقط تغییر مجاز و بدون گیم‌پلی/آرت |
| Git Index Validation | git ls-files، status، check-ignore، diff --cached --check و تطبیق بایت Index | موفق؛ ۲۶ فایل، خود JSON نیز Stage و در فهرست |
| ZIP Integrity | ZipFile.testzip، تطبیق فهرست و بایت با Index | موفق؛ CRC و تمام ۲۶ فایل یکسان |

چهار fixture منفی جدا از پروژه آزمایش شدند: تغییر نام یک مرحله، تغییر سرعت به281،
لینک نسبی خراب و اضافه‌کردن .gd غیرمجاز. هر چهار با exit غیرصفر رد شدند؛ این
شکست مورد انتظار validator است، نه خطای حل‌نشده در پروژه اصلی. fixtureها تحویل نمی‌شوند.
تمام تست‌های فاز یک در جدول QA با PLANNED / NOT RUN هستند و گیم‌پلی تست نشده است.

بازبینی مهندسی مستقل از تست مکانیکی: تطابق MVP/مناطق، ده نام/شناسه، ورودی لمس و
منو، مصرف Buffer/Coyote، stateهای تلاش، تقدم terminal، مالک Score/Save، رکورد فقط
موفقیت، محدودیت Asset و gateها بررسی شد. این بازبینی تأیید کیفیت واقعی بازی نیست.
تست مکانیکی معنی کامل همه متن‌ها یا کیفیت داستان را اثبات نمی‌کند. لینک‌های نسبی
بررسی شده‌اند؛ HTTP همه URLها توسط تست محلی بررسی نشده است. منابع رسمی CharacterBody2D،
Area2D، input، pause و Node در وب باز و بررسی شدند.

## ۸. وضعیت QA-001

باز؛ تصویر واقعی Main Scene و مرکز بودن عنوان تأیید نشده است. بررسی گرافیکی جدید
در ۰.۲ اجرا نشد؛ شواهد ناموفق R1 حفظ شده‌اند. probe فعلی وضعیت PATH/متغیرهای نمایشگر
را در JSON ثبت کرده است. مسیر آزمون روی میزبان گرافیکی دیگر، ثبت hash/نسخه/driver،
اجرای F5/F6، آزمون نسبت تصویر، screenshot و log در QA_TEST_PLAN.md تعریف شده است.
QA-001 پیش از شروع هر پیاده‌سازی عملی Prototype باید تعیین تکلیف شود.

## ۹. وضعیت QA-002

باز؛ Android Export و نصب روی دستگاه اجرا نشده‌اند. فهرست JDK17، SDK و بسته‌ها،
Templates منطبق و شواهد لازم برای رفع در QA ثبت شده است. probe فعلی javac/adb/sdkmanager
را نیز ثبت می‌کند؛ ممیزی قبلی با تست Android موفق جایگزین نشده است.
QA-002 باید پیش از مرحله Android Export رفع شود. کلید Release ساخته نشده است.

## ۱۰. وضعیت Git

مخزن محلی بدون Commit و Remote؛ فایل‌های جدید و اصلاح‌شده Stage شده‌اند.
مجموع Index و ZIP: **۲۶ فایل**، شامل ۱۸ فایل پایه و ۸ فایل جدید. فهرست کامل و
خروجی دستورها در git_validation_results.json ثبت است. ابتدا همه مسیرهای تحویل Stage،
سپس ls-files ثبت، سپس JSON مجدداً Stage و در پایان بایت دیسک/Index/ZIP مقایسه شد.
در نتیجه مغایرت فایل خودارجاع قبلی تکرار نشده است. ZIP .git، .godot، باینری موتور،
fixtureها و خروجی ساخت ندارد؛ همه پوشه‌های خالی پایه را حفظ می‌کند. هیچ push انجام نشده است.

## ۱۱. مشکلات باقی‌مانده

QA-001 و QA-002 بازند؛ تست‌های فاز یک اجرا نشده‌اند. اعداد و طرح‌های محصولی پیشنهادی
به تأیید مدیر و سپس داده Prototype نیاز دارند. GDD قدیمی مستقل در R1 نبود؛ تفصیل
داستان/مخاطب/نام مناطق با برچسب پیشنهادی نگارش شد، نه ادعای بازیابی سند قدیمی.
چیدمان مختصات دقیق مرحله، هنر نهایی و پیاده‌سازی سیستم‌ها عمداً متعلق به مرحله آینده‌اند.
نقص فنی بازِ جدید در آزمون‌های الزامی مستندسازی مشاهده نشد.
