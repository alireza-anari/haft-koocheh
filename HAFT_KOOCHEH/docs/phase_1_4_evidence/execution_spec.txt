## ۵. وظیفه A — ساخت Coin

فایل جدید:

`scripts/gameplay/coin.gd`

صحنه جدید:

`scenes/collectibles/coin.tscn`

### ساختار صحنه

Root: `Area2D`

فرزندان:

- CollisionShape2D
- Polygon2D

نمایش Polygon2D صرفاً Placeholder است.

از RigidBody2D استفاده نکن.

### تنظیم Collision

| مورد | مقدار |
|---|---|
| Collision Layer | 8 |
| Collision Mask | 2 |
| Monitoring | true |
| Player Layer | 2 |

تنظیمات باید با Collision Layers مرحله ۱.۳ سازگار باشند.

### شناسه سکه

هر سکه باید دارای:

`coin_id: StringName`

باشد.

شرایط:

- شناسه خالی ممنوع.
- شناسه در هر Level یکتا باشد.
- شناسه ثابت و مستقل از Instance ID باشد.
- شناسه در Restart تغییر نکند.
- شناسه تکراری در یک چیدمان خطای طراحی محسوب شود.

نمونه شناسه آزمایشی:

- `bazaar_01_coin_001`
- `bazaar_01_coin_002`
- `bazaar_01_coin_003`

### Signal

`pickup_requested(coin_id: StringName)`

Coin فقط درخواست جمع‌آوری صادر می‌کند.

Coin حق ندارد مستقیماً امتیاز را تغییر دهد.

### رفتار جمع‌آوری

هنگام `body_entered`:

1. بررسی کن Body دقیقاً Player فعال همان تلاش باشد.
2. بررسی کن Player در وضعیت RUNNING باشد.
3. بررسی کن Coin قبلاً pending یا collected نشده باشد.
4. درخواست pickup فقط یک بار صادر شود.
5. Coin تا دریافت تصمیم Level در حالت pending بماند.

### متد تأیید

`confirm_pickup()`

فقط پس از تأیید ScoreManager اجرا شود.

رفتار:

- علامت collected ثبت شود.
- pending پاک شود.
- monitoring خاموش شود.
- CollisionShape2D به‌صورت deferred غیرفعال شود.
- نمایش Coin حذف یا مخفی شود.

تغییر Collider داخل flush فیزیک ممنوع است.

برای رویداد تکراری یا coin_id تکراری، مسیر rejection امن داشته باش.

## ۶. وظیفه B — ساخت ScoreManager

فایل جدید:

`scripts/systems/score_manager.gd`

ScoreManager باید Node فرزند LevelController باشد.

نباید Autoload شود.

نباید زیر Player یا World قرار گیرد؛ چون در Restart جهان باید نمونه ScoreManager باقی بماند و فقط داده تلاش بازنشانی شود.

### API الزامی

`reset_run(level_id: StringName)`

`record_coin(coin_id: StringName) -> bool`

`build_result(completed: bool) -> Dictionary`

### متغیرها

- `level_id`
- `coins_collected`
- `score`
- مجموعه شناسه‌های جمع‌آوری‌شده

### فرمول امتیاز

طبق DEC-022 و R1-D03:

`score = 10 * coins_collected`

هر سکه ۱۰ امتیاز آزمایشی دارد.

این فرمول هنوز تصمیم نهایی اقتصادی محصول نیست.

بدون تأیید مدیر پروژه آن را تغییر نده.

### رفتار record_coin

اگر coin_id جدید و معتبر باشد:

- شناسه ثبت شود.
- coins_collected یک واحد افزایش یابد.
- score ده واحد افزایش یابد.
- true برگردانده شود.
- Signal تغییر امتیاز صادر شود.

اگر coin_id قبلاً ثبت شده باشد:

- امتیاز افزایش نیابد.
- شمارنده تغییر نکند.
- false برگردد.

امتیاز منفی یا اعشاری وجود ندارد.

### Signal

`score_changed(score: int, coins: int)`

پس از reset و پس از پذیرش سکه جدید صادر شود.

### خروجی build_result

Dictionary دقیقاً شامل:

- `level_id`: String
- `score`: int
- `coins`: int
- `completed`: bool

باشد.

ScoreManager نباید Player، UI، فایل ذخیره یا SaveManager را مدیریت کند.

## ۷. وظیفه C — اتصال به LevelController

فایل موجود:

`scripts/gameplay/level_controller.gd`

باید توسعه یابد.

### مالکیت

LevelController تنها مالک تصمیم پذیرش جمع‌آوری سکه است.

Coin فقط درخواست می‌دهد.

ScoreManager فقط وضعیت امتیاز را نگهداری می‌کند.

LevelController:

1. Coin را شناسایی می‌کند.
2. هویت Player را بررسی می‌کند.
3. Attempt ID را بررسی می‌کند.
4. تعلق Coin به World فعال را بررسی می‌کند.
5. وضعیت RUNNING را بررسی می‌کند.
6. درخواست معتبر را صف‌بندی می‌کند.
7. ScoreManager.record_coin را فراخوانی می‌کند.
8. فقط در صورت پذیرش، confirm_pickup را اجرا می‌کند.

### کنترل رویدادهای تأخیری

مانند مرحله ۱.۳:

- WeakRef حفظ شود.
- Attempt ID حفظ شود.
- Instance ID منبع بررسی شود.
- رویداد World قبلی رد شود.
- Coin نمونه قدیمی نباید روی تلاش تازه اثر بگذارد.

### تقدم Failure و Coin

این قانون قطعی است:

**Failure > Coin**

اگر در یک پنجره فیزیک، Coin و Hazard هم‌زمان فعال شوند:

- Failure برنده است.
- Score تغییر نمی‌کند.
- confirm_pickup اجرا نمی‌شود.
- وضعیت Player به DEAD می‌رود.
- فقط یک run_failed صادر می‌شود.

ترتیب Callbackها نباید نتیجه را تغییر دهد.

از معماری صف و داوری تیک بعدی موجود استفاده کن.

منطق فعلی fall > hazard > wall باید دقیقاً حفظ شود.

### محدودیت وضعیت Level

در این مرحله وضعیت‌های فعلی:

- READY
- RUNNING
- FAILED

حفظ شوند.

ساخت سیستم واقعی Finish و COMPLETED در محدوده این مرحله نیست.

## ۸. وظیفه D — اتصال به Restart

فایل:

`scripts/gameplay/level_controller.gd`

ScoreManager باید در هر Restart بازنشانی شود.

ترتیب:

1. World قبلی متوقف شود.
2. World قبلی آزاد شود.
3. Attempt ID افزایش یابد.
4. World تازه ساخته شود.
5. Player تازه ساخته شود.
6. Coinهای تازه Instance شوند.
7. Coinها به Player و Attempt فعال متصل شوند.
8. ScoreManager.reset_run فراخوانی شود.
9. Score برابر صفر شود.
10. coins_collected برابر صفر شود.
11. Player پس از استقرار زمین RUNNING شود.

تمام Coinهای جمع‌آوری‌شده باید در تلاش جدید دوباره قابل مشاهده باشند.

بازنشانی صرفاً موقعیت Player کافی نیست.

ScoreManager نباید در هر تیک یا هنگام start_run به‌صورت ناخواسته reset شود.
